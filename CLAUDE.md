# Strata-Test: notes for Claude

A monorepo of Nava Strata apps styled with the Colorado Design System (CoDS).
Read README.md first.

## Rules

- Create apps only with `bin/new-app <rails|nextjs|flask> <name>`. Never copy
  template files by hand. The script installs the template plus its infra
  layer through `nava-platform` (which records answers in
  `.template-application-*/<name>.yml` and `.template-infra/app-<name>.yml`),
  applies the CoDS/Strata customizations, commits, and runs the tests.
- All pinned versions are in `stack/versions.env`. Change versions there and
  re-run the scripts; don't edit pinned URLs or refs inside apps.
- Customizations live in `bin/new-app` (`customize_*` functions) and
  `stack/cods/`. They must stay idempotent: `bin/new-app --reapply <app>`
  on an up-to-date app should produce no diff.
- After `nava-platform app update`, run `bin/new-app --reapply <app>`.
- UI markup: use USWDS markup paired with CoDS classes, e.g.
  `class="usa-button cods-button"`. CoDS fixtures (canonical markup) are at
  `<app>/node_modules/@coloradodigitalservice/colorado-design-system/dist/fixtures/`.
  Put CoDS gap fixes in `stack/cods/_cods-compat.scss`, never in a single app.
- Rails apps: build features with the Strata SDK (`strata` gem: ApplicationForm,
  Case, flows, form builder, `Strata::US::*` components) before writing custom
  code. SDK docs: https://github.com/navapbc/strata-sdk-rails/tree/main/docs
- Don't load CoDS's JS bundle alongside `uswds.min.js`. Both bind the accordion.

## Code review

The `Claude Code Review` workflow reviews every PR using this file. Flag as
important (fix before merge):

- **Bypassing the generator:** an app or template file created or changed by
  hand when `bin/new-app` / `nava-platform` should own it, or a CoDS fix made
  in one app's copy of `_cods-compat.scss` / `bin/cods-css` instead of
  `stack/cods/`.
- **Non-idempotent customizations** in `bin/new-app` (a second `--reapply`
  would change files), or edits that break on a template update.
- **Pins outside `stack/versions.env`:** hard-coded CoDS/USWDS/template/SDK
  versions or URLs in apps or scripts.
- **UI markup:** USWDS classes without their CoDS pair where CoDS has the
  component; inline styles or custom CSS where a CoDS/USWDS component exists.
- **Accessibility (WCAG 2.1 AA):** missing labels, legends, or alt text;
  color-only meaning; focus traps; headings out of order; form errors not
  announced; non-semantic click targets.
- **Rails:** reimplementing what the Strata SDK provides (ApplicationForm,
  Case, flows, form builder, `Strata::US::*` components); missing Pundit
  authorization on a controller action; strong-params gaps.
- **Security and privacy:** secrets, tokens, or real personal data (names,
  SSNs, addresses, case details) in code, fixtures, seeds, or logs; PII
  written to logs; unvalidated input reaching SQL, shell, or file paths.
- **Infra:** Terraform edits that should be made via the Nava infra
  template's variables or `app-config`, or that weaken encryption, logging,
  or network restrictions.
- **CI:** skipped, disabled, or deleted tests or checks.

Do not report: formatting the linters already enforce, files generated by
the Nava templates and left unchanged, lockfile contents, or vendored
CoDS/USWDS output.

## Tax prototype (tax-portal + tax-engine)

- Read docs/tax-portal/tax-prototype-architecture.md before changing it.
- docs/tax-portal/direct-file-lessons.md lists what the prototype still lacks
  compared with IRS Direct File; keep it current when you close a gap.
- The portal never does tax math. All amounts come from tax-engine
  (`TaxEngine.client`); specs use `TaxEngine::FakeClient`.
- Every expected dollar amount in tax-engine tests came from PolicyEngine and
  should be re-derived, not edited, when rules change.
- Demo people use SSNs in area 000 (never issued). Never add real personal data.
- Taxpayer-facing text lives in `tax-portal/config/locales/tax/` in English and
  Spanish; add both. Follow the Direct File content style: plain words, say
  what to do in error messages, no personal data in titles, links or buttons.
- After changing either app: `bin/demo test` (set
  `E2E_CHROMIUM_PATH=/opt/pw-browsers/chromium` in cloud sessions).

## Running things

- Toolchain: `bin/setup-env --postgres`, then check with `bin/doctor`.
  Ruby versions are managed by rbenv; scripts put `$(rbenv root)/shims` on PATH.
- Check an app: `bin/new-app --verify <app>`.
  - Rails: `bundle exec rspec`. CSS is built by `npm run build:css`.
  - Next.js: `npm run lint && npm run ts:check && npm test && npm run build`.
  - Flask (native): `PY_RUN_APPROACH=local make test`, with `local.env` loaded and
    `DB_NAME=<app_with_underscores>`.
- Local Postgres: 127.0.0.1:5432, role `app` / `secret123`. Each app uses its own
  database name (`<app>_development`, `<app>_test`).
- Repo lint (also run in CI): `shellcheck bin/**`, `actionlint`,
  `make infra-lint-terraform`.
